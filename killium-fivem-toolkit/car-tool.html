Written as the author field in fxmanifest.lua for the whole pack. To tag individual vehicles by creator, use the Creator column on the Vehicles tab — it wraps that vehicle's own folder in [tag] (e.g. data/[Police]/[killium]/t20/) and shows as spawncode-creator in the table.
Everything bundled into one download.

Correct FiveM structure

✦ data/[category]/[creator]/spawnname/ — each vehicle gets its own folder, bracketed by category and (optionally) its own creator tag, set per-vehicle in the Vehicles table
✦ stream/[category]/[creator]/spawnname/ — that vehicle's own binary stream files (.yft, .ytd, .ybn…), matched by filename
✦ handling.meta / carcols.meta / carvariations.meta are each trimmed down to just this vehicle's entry and placed alongside its vehicles.meta — self-contained, exactly like a hand-built pack
✦ Anything that can't be tied to one specific vehicle — an oddly-named stream file, a shared layout, a multi-vehicle handling entry — stays in a folder named after the resource it came from, in the same sub-path it originally had, so nothing is silently dropped or renamed. Check the Unmatched tab to see exactly where each one came from and optionally move it into a specific vehicle's folder instead. Only included in Single .zip mode — split downloads skip these to avoid duplicating them across every piece.
✦ fxmanifest.lua — uses data/**/*.meta wildcards so FiveM loads all of them automatically, no matter how deep. Each split .zip gets its own fxmanifest.lua, so every piece is a standalone resource.
Meta files are never merged together — each vehicle keeps its own copy. This avoids XML corruption and ID conflicts.
